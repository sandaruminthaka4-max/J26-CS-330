## Quick Start

### Step 0 — Install dependencies
```bash
pip install -r requirements.txt
```

### Step 1 — Download datasets

**CICIoMT2024** (WiFi + MQTT subset):
- Kaggle: https://www.kaggle.com/datasets/search?q=CICIoMT2024
- Zenodo: https://zenodo.org/records/10519703
- Place CSV files in: `data/raw/ciciomt2024/`

**CICIoT2023**:
- Kaggle: https://www.kaggle.com/datasets/madhavmalhotra/unb-cic-iot-dataset
- Direct: https://www.unb.ca/cic/datasets/iotdataset-2023.html
- Place CSV files in: `data/raw/ciciot2023/`

Check availability:
```bash
python src/download_datasets.py
```

### Step 2 — Feature mapping & merge
```bash
python src/01_feature_mapping.py
```

### Step 3 — Train IoMT classifier (Stage 1)
```bash
python src/02_iomt_classifier.py
```

### Step 4 — Train anomaly detector (Stage 3)
```bash
python src/03_anomaly_detector.py
```

### Step 5 — Start API
```bash
python api/app.py
```

## Documented Limitations

| Limitation | Impact | Mitigation |
|---|---|---|
| No explicit MITM label in CICIoMT2024 | Cannot train a "MITM confirmed" classifier | Use "Suspicious" label; detect MITM-enabling attacks (ARP Spoofing) |
| MQTT packet-level fields absent in CSV | Cannot extract msgtype, flags, keepalive from CSVs | Use PCAP parsing with Scapy/PyShark for full MQTT analysis |
| CICIoT2023 is consumer IoT, not enterprise non-IoT | IoMT vs Non-IoMT boundary is approximate | Document in methodology; validate on diverse captures |
| No non-IoMT ground truth in CICIoMT2024 | Cannot evaluate IoMT classifier on CICIoMT2024 alone | Dataset merger with CICIoT2023 provides the non-IoMT class |
